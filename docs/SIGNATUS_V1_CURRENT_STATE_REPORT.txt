1. OVERALL ASSESSMENT
=====================

Signatus v1 is a substantial functional prototype with a complete three-process
code path:

    PySide6 GUI
        <-> Core REST/WebSocket
    Python Core
        <-> AI REST/WebSocket
    Python AI Service
        <-> OpenCV VideoCapture
    USB camera

    AI Service -- local shared memory --> GUI preview and YOLO overlays

The safety-critical Core rules are implemented and unit-tested. The AI adapters,
shared-memory transport, face embedding backend, and redesigned GUI are also
implemented.

It is not currently production-ready or fully runnable end-to-end on this
machine:

- No /dev/video0 or other /dev/video* device exists.
- The current .env enables AI tracking and selects /dev/video0, but tracking
  cannot operate until that camera device is available.
- The only worksite file contains placeholder 3-dimensional face embeddings;
  the included SFace model produces 128-dimensional descriptors. Consequently,
  no real worker can currently receive AUTHORIZED or PPE_VIOLATION.
- The 0.35 face-match threshold has not been experimentally validated.
- Camera, ByteTrack, real-person face recognition, PPE inference,
  shared-memory preview, and HDMI rendering have not been exercised together
  on the deployment hardware.
- The workspace is not a functional Git checkout. .git/ exists but is empty,
  and git status fails.
- The active virtual environment is Python 3.14.4 rather than the documented
  Python 3.11 environment and contains conflicting OpenCV installations.

Current automated result:

- unittest: 60 tests passed.
- pytest: 60 tests and 11 subtests passed.
- Ruff: passed.
- Local OpenVINO inference on a blank image: passed.
- YuNet/SFace model initialization and blank-image inference: passed with
  NO_FACE.
- Real-camera end-to-end test: not possible because no camera device exists.

3. AI SERVICE IMPLEMENTATION STATUS
===================================

3.1 Implemented and working at code/component-test level
--------------------------------------------------------

FastAPI service
~~~~~~~~~~~~~~~

src/signatus_ai/app.py defines:

- GET /health
- POST /commands/tracks/{track_id}/embedding
- POST /commands/tracks/{track_id}/ppe
- WS /ws/events

The lifespan starts UltralyticsOpenVINOTracker.run() only when
SIGNATUS_AI_TRACKING_ENABLED is true.

Camera and YOLO tracking
~~~~~~~~~~~~~~~~~~~~~~~~

UltralyticsOpenVINOTracker:

- Opens cv2.VideoCapture(camera_source).
- Loads YOLO(model_path).
- Calls model.track(source=frame, persist=True, tracker="bytetrack.yaml",
  verbose=False).
- Converts YOLO boxes into Detection and TrackedPerson.
- Requires a non-null ByteTrack ID before treating a Person detection as a
  tracked person.
- Stores the latest frame, boxes, and people in DetectionCache.
- Emits PERSON_SEEN for each currently tracked person.
- Emits TRACK_LOST after the configured 1.5-second absence.
- Runs _read_snapshot() in asyncio.to_thread(), keeping capture and YOLO
  inference off the AI event loop.

The OpenVINO model successfully performed a blank 640x640 inference in the
current environment.

Face backend
~~~~~~~~~~~~

OpenCVYuNetSFaceEmbedder:

- Crops the requested tracked-person rectangle.
- Uses cv2.FaceDetectorYN with configurable score, NMS, and top-k.
- Requires exactly one detected face.
- Uses cv2.FaceRecognizerSF.alignCrop() and .feature().
- Returns distinct NO_FACE, MULTIPLE_FACES, LOW_QUALITY, and ERROR statuses.
- Rejects empty, zero-norm, and non-finite descriptors.

The included models initialize successfully. A blank-frame check returned
NO_FACE, as expected.

PPE cache behavior
~~~~~~~~~~~~~~~~~~

get_cached_ppe():

- Returns NO_CACHED_FRAME when empty.
- Returns TRACK_NOT_FOUND when the requested track is absent.
- Uses SinglePersonFrameAssociation.
- Returns ASSOCIATION_UNRESOLVED for zero, multiple, or mismatched people.
- Returns all non-Person class names for the sole requested person.

Shared-memory preview
~~~~~~~~~~~~~~~~~~~~~

SharedMemoryFramePublisher:

- Is the sole creator/owner.
- Uses two frame slots and two detection-metadata slots.
- Uses an odd/even seqlock.
- Publishes raw BGR pixels and same-inference class/confidence/box metadata.
- Treats preview failures as nonfatal to tracking.
- Unlinks only a segment it created.

Event fan-out
~~~~~~~~~~~~~

EventHub supports multiple WebSocket subscribers through bounded size-64
queues and drops the oldest queued event when a subscriber falls behind.

3.4 Important AI limitations and risks
--------------------------------------

1. Tracking is disabled by default. With current defaults the AI service
   starts, but creates no shared-memory segment, reads no camera, caches no
   detections, and emits no events.

2. No camera exists on this host. Enabling tracking currently fails at
   VideoCapture(0).

3. Tracker task failure is not surfaced reliably. If _open(), camera reading,
   or inference raises, the tracking task terminates. /health still reports
   status ok and the configured tracking_enabled value; it does not report
   task failure.

4. No camera retry loop exists. A transient disconnection ends tracking rather
   than reopening the device.

5. Face inference is synchronous on the AI event loop. generate() is async,
   but executes _generate_sync() directly. This can block other AI HTTP or
   WebSocket work during SFace processing.

6. Exceptions occurring after the shared-memory writer marks the buffer odd
   can leave the current mapping unreadable until a later successful
   publication or service restart.

7. Preview timestamp_ns is captured before YOLO inference; FrameSnapshot
   captured_at is assigned after inference. They describe the same frame but
   are not the same clock sample.

8. A slow Core subscriber can silently lose AI events once its 64-entry queue
   fills.


4. CORE IMPLEMENTATION STATUS
=============================

4.1 Implemented and working at code/unit-test level
---------------------------------------------------

State machine
~~~~~~~~~~~~~

CoreController owns:

- CoreState.STANDBY
- CoreState.AUTHORIZATION
- Selected worksite.
- Identity matching.
- PPE policy application.
- Final GUI outcomes.

A PERSON_SEEN event starts authorization only when a worksite is selected,
Core is STANDBY, the track is not handled, and its retry cooldown has elapsed.
Core returns to STANDBY in a finally block.

Track lifecycle
~~~~~~~~~~~~~~~

InMemoryTrackGuard:

- Stores TrackRecord objects in a Python dictionary.
- Tracks last_seen_at, handled, face_failures, and retry_not_before.
- Uses a one-second retry cooldown.
- Marks the track handled after three face failures.
- Marks completed decisions handled.
- Deletes all state for a track on TRACK_LOST.
- Loses all track state on process restart, intentionally.

Identity matching
~~~~~~~~~~~~~~~~~

find_best_match():

- Computes cosine similarity.
- Rejects empty, zero, or dimension-mismatched vectors.
- Selects the highest-scoring worker.
- Applies the configured 0.35 minimum similarity.

PPE policy
~~~~~~~~~~

    Semantic PPE  Positive  Negative
    helmet        helmet    no_helmet
    gloves        gloves    no_gloves
    vest          vest      none
    boots         boots     no_boots
    goggles       goggles   no_goggle

Behavior:

- Negative wins over positive.
- Missing positive is noncompliant.
- none marks every required PPE item missing.
- Any non-OK AI PPE response becomes an empty detection set and fails closed.

Four distinct outcomes
~~~~~~~~~~~~~~~~~~~~~~

- AUTHORIZED
- PPE_VIOLATION
- UNAUTHORIZED
- FACE_CAPTURE_FAILED

FACE_CAPTURE_FAILED remains distinct and includes retry information.

Core API
~~~~~~~~

- GET /api/health
- GET /api/worksites
- POST /api/worksites/{worksite_id}/select
- GET /api/state
- WS /ws/gui

AI client
~~~~~~~~~

AIServiceClient:

- Uses httpx.AsyncClient with a five-second timeout for commands.
- Uses a reconnecting WebSocket loop for events.
- Converts command transport failures into ERROR.
- Retries AI event connection every second.

4.2 Stubbed or placeholder behavior
-----------------------------------

- The worksite repository contains only example data.
- Both configured worker embeddings are placeholders.
- No worker display name exists; only worker_id.
- GUISignalHub is a simple in-memory broadcast set with one global latest
  signal.
- Core health is a minimal process/state check, not dependency health.
- Worksite JSON handling is direct dictionary access rather than a validated

4.3 Not yet started or not implemented
--------------------------------------

- Real enrolled-worker data.
- Face-threshold experiment.
- Worksite JSON schema validation and migration/versioning.
- Duplicate worksite/worker detection.
- Validation that all embeddings use the expected SFace dimension/backend.
- Worksite-change lifecycle policy for already-present tracks.
- Database or persistent state; intentionally excluded from v1.

4.4 Important Core limitations and risks
----------------------------------------

1. Current authorization cannot succeed. SFace produces 128 values; both
   enrolled examples have three. Dimension mismatch makes every valid face
   unauthorized.

2. Worksite selection is not synchronized with authorization.
   select_worksite() does not acquire the controller lock. A worksite can
   change while _authorize() is awaiting AI calls, potentially allowing the
   in-flight decision to use the new worksite.

3. Changing worksite does not clear track state. A person already marked
   handled remains handled after a new worksite is selected.

4. GUISignalHub.latest is not cleared on worksite selection. A reconnecting
   GUI can receive the last result from a previous worksite.

5. listen_forever() awaits handler(event) before reading the next WebSocket
   message. TRACK_LOST can be delayed while embedding/PPE calls run.

6. An unexpected controller exception can terminate the AI listener task
   without changing /api/health.

7. Core manually parses AI JSON instead of using shared Pydantic models.
   Returned track_id values are ignored, embedding elements and class lists
   are weakly validated, and negative event track IDs can be accepted.

8. Embedding and PPE commands separately request the latest cache and may
   operate on different frames.

9. Missing fields, malformed JSON, unknown PPE names, or invalid embedding
   contents in a worksite file can cause runtime exceptions.

10. Core reports status ok whether or not the AI Service is connected.

6. DATA CONTRACTS
=================

6.1 AI Service -> Core events
-----------------------------

Transport:

    ws://127.0.0.1:8001/ws/events

Schema:

    {
      "type": "PERSON_SEEN | TRACK_LOST",
      "track_id": 3,
      "captured_at": 1786980000.125
    }

Shared Pydantic model:

    class AIEvent(BaseModel):
        type: AIEventType
        track_id: int = Field(ge=0)
        captured_at: float

Behavior and flags:

- PERSON_SEEN is emitted repeatedly while a track remains visible.
- TRACK_LOST is emitted after the configured absence timeout.
- Events are not persisted or replayed.
- Subscriber queue size is 64.
- The schema matches the documented v1 schema.
- Core manually coerces fields rather than using the shared Pydantic model.
- No event sequence, frame ID, confidence, or box is sent to Core.
- captured_at is a Unix-seconds float assigned after inference.

6.2 Core -> AI commands and responses
-------------------------------------

Embedding command:

    POST /commands/tracks/{track_id}/embedding

No request body.

Response:

    {
      "track_id": 3,
      "status": "OK | NO_FACE | MULTIPLE_FACES | LOW_QUALITY | ERROR",
      "embedding": [0.1, 0.2, 0.3]
    }

embedding is null on failures.

PPE command:

    POST /commands/tracks/{track_id}/ppe

No request body.

Response:

    {
      "track_id": 3,
      "status": "OK | NO_CACHED_FRAME | TRACK_NOT_FOUND |
                 ASSOCIATION_UNRESOLVED | ERROR",
      "detected_classes": ["helmet", "no_gloves", "boots"],
      "captured_at": 1786980000.125
    }

Pydantic normally includes empty/default fields on failures:

    {
      "track_id": 3,
      "status": "NO_CACHED_FRAME",
      "detected_classes": [],
      "captured_at": null
    }

Flags:

- Schemas match the documented command design.
- Core ignores the response's returned track_id.
- No cache sequence ID links embedding and PPE responses.
- No freshness threshold is enforced.

6.4 Camera -> AI Service
------------------------

There is no JSON or network schema.

Actual interface:

    capture = cv2.VideoCapture(camera_source)
    ok, frame = capture.read()

Assumptions:

- ok is true.
- Frame is convertible to a NumPy array.
- Shape is height x width x 3.
- Type is uint8.
- Channel order is BGR.
- Ultralytics boxes refer to original capture coordinates.
- AI Service exclusively owns the camera.

Code default when SIGNATUS_CAMERA_SOURCE is unset:

    SIGNATUS_CAMERA_SOURCE=0

The current .env explicitly selects /dev/video0.

No camera negotiation, resolution, FPS, exposure, or backend selection is
implemented.

6.5 AI Service -> GUI preview contract
--------------------------------------

This bypasses Core and is presentation-only.

Shared memory default:

    signatus_camera_v1

Actual binary protocol version:

    FRAME_BUFFER_VERSION = 2

Header:

    <8s9IQQ4x

Fields:

    magic
    version
    header_size
    slot_capacity
    width
    height
    stride
    channels
    active_slot
    overlay_size
    sequence
    timestamp_ns
    padding

Constants:

- Header: 64 bytes.
- Two frame slots.
- Default frame-slot capacity: 6,220,800 bytes.
- Two overlay slots.
- Overlay-slot capacity: 65,536 bytes.
- Maximum detections: 1,024.
- Default total segment size: 12,572,736 bytes.

Detection payload:

    uint32 detection_count
    repeat:
        float32 x1
        float32 y1
        float32 x2
        float32 y2
        float32 confidence
        uint16 class_name_byte_length
        UTF-8 class_name bytes

Flags:

- This deviates from the original raw-BGR-only preview contract.
- The transport version is 2, but the segment name still contains _v1.
- Old v1 and current v2 processes are incompatible.
- Metadata carries no track ID and no policy/outcome data.
- AI and GUI must be upgraded/restarted together.


7. TRANSPORT MECHANISMS ACTUALLY IN USE
======================================

Camera -> AI
    Direct OpenCV device access through cv2.VideoCapture.

AI capture/inference -> AI async loop
    Worker thread through asyncio.to_thread().

AI tracker -> AI cache
    Direct calls protected by asyncio.Lock.

AI tracker -> AI event clients
    In-process asyncio.Queue objects through EventHub.

AI -> Core events
    WebSocket JSON at /ws/events.

Core -> AI embedding/PPE
    HTTP POST with JSON responses through httpx.AsyncClient.

Core controller -> GUI signal hub
    Direct async function call.

Core -> GUI outcomes
    WebSocket JSON at /ws/gui.

GUI -> Core worksite/state
    Qt QNetworkAccessManager HTTP GET/POST; state every 500 ms.

AI -> GUI preview
    POSIX shared memory through multiprocessing.shared_memory.

GUI shared memory -> widgets
    33 ms QTimer, detached QImage, Qt signal, and QPainter.

There are no direct Python calls between processes, no database, no message
broker, no MJPEG/WebRTC, and no Core video proxy.


8. DEVIATIONS FROM THE ORIGINAL/APPROVED SPECIFICATION
======================================================

8.1 Shared-memory preview v2
----------------------------

The original preview was raw BGR only. The current implementation adds
presentation-only YOLO class, confidence, and boxes to the same segment so the
GUI can draw accurate overlays without duplicate inference.

This is a process-boundary contract change and should be explicitly ratified.
docs/DEVELOPER_REPORT.md is stale because it still describes a BGR-only
preview.

8.2 Worksite REST extension
---------------------------

required_ppe was added to worksite list and selection responses so the GUI can
construct PPE rows. Core still owns evaluation and class policy.

8.3 Core-state polling
----------------------

The GUI polls /api/state every 500 ms rather than extending /ws/gui with state
transitions. Short authorization states can be missed and stale state failures
are silent.

8.4 Worker ID shown as worker name
----------------------------------

The Worker field shows worker_id because no human-name field exists.

8.5 Preview after inference
---------------------------

Frames are published after YOLO inference to atomically pair pixels and boxes.
Preview latency therefore includes inference time, and failed inference means
no publication for that frame.

8.6 Synchronous face processing
-------------------------------

SFace runs synchronously on the AI event loop because the code documents prior
executor hangs. This can temporarily block other AI service work.

8.7 Environment deviation
-------------------------

The canonical setup uses Python 3.11. The active environment uses Python
3.14.4. pyproject.toml technically permits it through >=3.11, but it is not the
documented deployment version.

-------------------------------

- Added overlays to shared memory rather than routing them through Core.

- Retained the old signatus_camera_v1 name.

12. DOCUMENTATION AND ENVIRONMENT INCONSISTENCIES

    contain required_ppe lists.


FINAL ARCHITECTURAL DISPOSITION
===============================

The codebase is best characterized as a well-tested functional v1 prototype
with the intended safety ownership boundaries intact, but with incomplete
production data, no working deployment camera, no true end-to-end validation,
and several lifecycle/contract decisions that should be ratified before calling
the architecture approved for deployment.
